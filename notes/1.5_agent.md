1、agent分工来建立边界：模型负责提出候选行动，系统负责限制行动空间，用户负责批准高风险边界。
2、agent是被约束的执行循环，目标、工具、状态、权限和停止条件缺一不可。
3、在编写 JSON 规范时，千万不要用 number 类型来代表256位数，因为很多语言的 JSON 解析器（包括 JavaScript）遇到这种超长数字会直接精度丢失变成科学计数法。永远用 string 类型来承载 Web3 的代币数量。
4、multi agent
它适合复杂工作流，但也会放大协调问题：上下文传递丢失、责任边界模糊、一个 Agent 的错误被另一个 Agent 当成事实、工具权限扩散。

做 Multi-Agent 时，要先问一个朴素问题：多个 Agent 是否真的减少复杂度？如果只是把一个不清楚的流程拆成多个不清楚的角色，系统会更难调试。
