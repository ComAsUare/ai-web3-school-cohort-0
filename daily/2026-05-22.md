### 🔧 二、知识整理方法升级

#### 2.1 为什么升级

前三天的学习是「逐章突击」模式：
- 优点：单点深入（LLM、交易解释器都做得很扎实）
- 问题：概念之间孤立，容易「学完就忘」；不知道每一章在整体中的位置

#### 2.2 新方法：三层知识索引

不再按章节顺序记笔记，而是按 **概念 → 代码 → 项目** 建立可追溯的索引：

```
📁 概念层 (what/why)
   ├── LLM: 概率生成、Token、Embedding、Attention、幻觉
   ├── Prompt: 软约束 vs 硬约束、System/User、Few-shot、注入攻击
   └── Web3: EOA vs SC钱包、交易生命周期、calldata 结构
        ↓ 映射到
📁 代码层 (how)
   ├── API 调用模式: openai client → .env 管理密钥
   ├── 链上查询模式: Blockscout API → JSON 存储 → 结构化解析
   └── 安全分析模式: calldata → 风险等级 → 行动建议
        ↓ 组合为
📁 项目层 (build)
   ├── 交易解释器 (认知层 + 保护层)
   ├── 风险摘要 Agent (行动层 + 保护层)
   └── [下一步] Agent 自动执行交易 (行动层)
```

### 💡 Insights & Reflections | 收获与思考

**What I Learned | 今日收获**:
- **大局观的价值**：三天密集学习后停下来看全景图，发现交易解释器无意中已经横跨了认知层+保护层，这说明「项目驱动」比「逐章学习」更高效
- **五层框架**是最好的组织原则：AI×Web3 不是 AI + Web3 的简单拼接，而是五个层次的垂直整合
- **Prompt 章节的核心教训**：Prompt 是软约束，安全必须是硬约束。这个原则直接适用于交易解释器的 LLM 安全分析
- **知识整理不是记更多笔记，而是建立更少的索引**：三层索引（概念→代码→项目）比逐章笔记本更可持续

**Problems Encountered | 遇到的问题**:
1. 前三天的学习产出虽然扎实，但在 repo 中的组织方式不利于快速回顾 — 需要重组 handbook-feedback/
2. 交易解释器和风险摘要是两个独立项目，但它们共享大量代码模式（API 调用、JSON 解析）— 应该提取公共模块
